## الباب 1: الصورة الكبيرة والمشروع متقسم إزاي

### القالب ولا البلجن؟

دي القاعدة اللي بيمشي عليها مطوّرين ووردبريس:

- **القالب هو الشكل:** إزاي الصفحات بتتعرض، يعني ملفات HTML وCSS والقوالب. لو غيّرت القالب، الشكل يتغيّر والبيانات تفضل زي ما هي.
- **البلجن هو الوظيفة:** البيانات والمنطق، يعني الجداول والصلاحيات والحسابات ومسارات الـ API. لو غيّرت القالب، البلجن يفضل شغال.

علشان كده نظام الحضور (المخدومين، والجلسات، وتسجيل الحضور) معمول كبلجن مش جوه القالب. لو الكنيسة غيّرت شكل الموقع بعد سنة، بيانات الحضور ماتضيعش.

### بنية المستودع

| المسار | المحتوى |
|---|---|
| `design/` | نماذج HTML المعتمدة، وهي المرجع للشكل اللي هنحوّله لقالب |
| `wordpress/themes/st-mina/` | القالب |
| `wordpress/plugins/st-mina-attendance/` | البلجن |
| `docs/design.md` | نظام التصميم وقواعد حساب الحضور |
| `docs/dev-setup.md` | التشغيل والرفع |

### البادئة

ووردبريس بيشغّل كود كل البلاجن والقالب في نفس المكان. لو بلجنين عرّفوا دالة بنفس الاسم، الموقع يقع بخطأ قاتل. علشان كده كل حاجة عندنا ليها بادئة ثابتة:

| النوع | البادئة |
|---|---|
| الدوال والإعدادات والجداول | `stmina_` |
| الثوابت | `STMINA_` |
| مسارات الـ API | `stmina/v1` |

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/plugins/plugin-basics/best-practices/#prefix-everything
```

## الباب 2: البيئة وووردبريس على الاستضافة

### ليه هوستنجر مش فيرسل؟

ووردبريس محتاج لغة `PHP` شغالة على سيرفر طول الوقت، وقاعدة بيانات `MySQL`، ومكان تتحفظ فيه الملفات المرفوعة. أما فيرسل فمبني للمواقع الثابتة وتطبيقات JavaScript، فمش بيشغّل ووردبريس. علشان كده نماذج التصميم على فيرسل، والموقع الحقيقي على هوستنجر.

### الدومين الفرعي المؤقت

- **الرابط:** عملنا دومين فرعي في فولدر لوحده.
```
st-mina.abanoubmaurice.com  →  public_html/st-mina
```
- **ليه مؤقت؟** الموقع بيتبني ويتجرّب هنا، وعند الإطلاق (المهمة 25) بينتقل لدومين الكنيسة بتحويل نوعه `301`، وده بيقول لجوجل والمتصفحات إن العنوان اتنقل نهائيًا.
- **ليه موقع نضيف؟** كان فيه موقع قديم عليه ثيم تجربة لمشروع تاني، بإعدادات إنجليزي ومن الشمال لليمين. البداية النضيفة أسهل وأأمن من تنضيف موقع قديم.

### تركيب ووردبريس

اتركّب من لوحة هوستنجر، من صفحة المُركِّب التلقائي. ودي ملاحظات مهمة:

- **كلمة سر المدير** بيختارها صاحب الموقع بنفسه، ومابتتبعتش لحد.
- **اسم المستخدم** الأفضل مايكونش `admin` ولا أول جزء من الإيميل، لأن دول أول حاجة بيجرّبها اللي بيحاولوا يخترقوا المواقع.
- **قاعدة البيانات** لكل موقع ووردبريس واحدة لوحده، وكلمة سرها مختلفة عن كلمة سر المدير.

### الإعدادات الأساسية بعد التركيب

| الإعداد | مكانه في اللوحة | القيمة | ليه |
|---|---|---|---|
| اسم الموقع والوصف | `Settings → General` | الاسم العربي، و"عرب العيايدة، الجبل الأصفر" | القالب بيعرضهم بدالة `bloginfo()`، فمش مكتوبين في الكود |
| لغة الموقع | `Settings → General → Site Language` | العربية | بتحمّل ملفات الترجمة، وبتخلّي الصفحات من اليمين للشمال |
| التوقيت | `Settings → General → Timezone` | القاهرة | مواعيد الجلسات والحضور بتتسجّل بتوقيت مصر |
| محركات البحث | `Settings → Reading` | مقفول | الموقع المؤقت مايظهرش في جوجل |

ولما محركات البحث بتتقفل، ووردبريس بيحفظ الإعداد ده بقيمة صفر، وبيضيف السطر ده في كل صفحة:
```html
<meta name="robots" content="noindex, nofollow">
```

### لغة الموقع غير لغة اللوحة

ووردبريس فيه لغتين منفصلتين:

| النوع | مكانها | بتأثر على |
|---|---|---|
| لغة الموقع | `Settings → General` | اللي الزوار بيشوفوه |
| لغة المستخدم | `Users → Profile → Language` | لوحة التحكم للمستخدم ده بس |

فينفع الموقع يبقى عربي، واللوحة إنجليزي للمطوّر، وعربي لمحرر المحتوى.

📖 التوثيق الرسمي:
```
https://wordpress.org/documentation/article/installing-wordpress-in-your-language/
```

## الباب 3: القالب وأقل ملفات يحتاجها

### القالب عبارة عن فولدر

القالب فولدر جوه مسار `wp-content/themes/` على السيرفر، وووردبريس بيدوّر جوّاه على الملفات اللي يعرض بيها الموقع. وده قالبنا:

```
st-mina/
├── style.css      ← بطاقة تعريف القالب + التنسيق
├── index.php      ← الصفحة اللي بتتعرض
└── functions.php  ← إعدادات وكود القالب (الباب 4)
```

أقل حاجة يحتاجها القالب ملفين بس: ملف `style.css` وملف `index.php`. ومن غير أي واحد منهم، القالب مش هيظهر في صفحة القوالب في اللوحة.

### ملف `style.css` كبطاقة تعريف

أول جزء في الملف تعليق عادي في CSS، لكن ووردبريس بيقراه علشان يعرف القالب:

```css
/*
Theme Name: St Mina
Theme URI: https://github.com/Abanoub-git-hup/church-st-mina
Description: قالب كنيسة السيدة العذراء ومارمينا والبابا كيرلس السادس. ...
Author: Abanoub S. Maurice
Version: 0.1.0
Requires at least: 6.5
Requires PHP: 8.0
Text Domain: st-mina
*/
```

| السطر | إجباري؟ | فايدته |
|---|---|---|
| `Theme Name` | أيوه، الوحيد الإجباري | الاسم في صفحة القوالب، ومن غيره ووردبريس يتجاهل القالب |
| `Version` | لا | رقم النسخة. بنزوّده مع كل تعديل، وبنستخدمه علشان المتصفح يحمّل الملف الجديد (الباب 4) |
| `Requires at least` | لا | أقل نسخة ووردبريس، ولو السيرفر أقدم مش هيسمح بالتفعيل |
| `Requires PHP` | لا | أقل نسخة من لغة PHP |
| `Text Domain` | لا | اسم الترجمة اللي بيتحط مع النصوص في الكود |

وبعد التعليق، الملف بيكمّل كود CSS عادي. الألوان متعرّفة كمتغيرات بنفس أسماء ملف `docs/design.md`، زي متغير `--umber-700`، علشان القالب يفضل متناسق مع نظام التصميم.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/themes/basics/main-stylesheet-style-css/
```

### ملف `index.php` وترتيب القوالب

لما زائر يفتح صفحة، ووردبريس بيدوّر على أنسب ملف ليها بترتيب اسمه `Template Hierarchy`. وده مثال لصفحتين:

| الصفحة | ووردبريس بيدوّر بالترتيب ده |
|---|---|
| الرئيسية | `front-page.php` ← `home.php` ← `index.php` |
| مقال | `single-post.php` ← `single.php` ← `singular.php` ← `index.php` |

يعني ملف `index.php` هو الاحتياطي الأخير لكل الصفحات، وعلشان كده إجباري. ودلوقتي قالبنا مافيهوش غيره، فأي رابط بيعرض نفس الصفحة المؤقتة. وفي المهمة الثانية هنضيف ملف `front-page.php` للرئيسية، وملفات لكل نوع صفحة.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/themes/basics/template-hierarchy/
```

### شرح ملف `index.php` جزء جزء

**أولًا: سطر الأمان**
```php
defined( 'ABSPATH' ) || exit;
```
الثابت `ABSPATH` بيعرّفه ووردبريس وهو شغال. ولو حد فتح الملف مباشرة من المتصفح، الثابت مش هيكون موجود، فالملف يقفل فورًا من غير ما يطلّع أي حاجة. والسطر ده موجود في أول كل ملف PHP عندنا.

**ثانيًا: لغة الصفحة واتجاهها**
```php
<html <?php language_attributes(); ?>>
```
دالة `language_attributes()` بتكتب لغة الصفحة واتجاهها من إعداد لغة الموقع، والنتيجة كده:
```html
<html lang="ar" dir="rtl">
```
علشان كده لما غيّرنا اللغة، الصفحة اتقلبت من اليمين للشمال من غير ما نلمس الكود. ومانكتبش الاتجاه بإيدنا أبدًا، نسيبه لووردبريس.

**ثالثًا: الترميز وعرض الموبايل**
```php
<meta charset="<?php bloginfo( 'charset' ); ?>">
<meta name="viewport" content="width=device-width, initial-scale=1">
```
السطر الأول بيحدد الترميز علشان العربي يظهر صح، والتاني بيخلّي الصفحة تتعرض صح على الموبايل.

**رابعًا: نقط ووردبريس في الصفحة**
```php
<?php wp_head(); ?>       // قبل </head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>  // بعد <body> مباشرة
...
<?php wp_footer(); ?>     // قبل </body>
```

| الدالة | فايدتها |
|---|---|
| `wp_head()` | المكان اللي ووردبريس والبلاجن بيحطوا فيه ملفات CSS وJS، وعنوان الصفحة، وسطر قفل محركات البحث |
| `wp_footer()` | زيها، بس في آخر الصفحة، وغالبًا لملفات JavaScript |
| `body_class()` | بتضيف أسماء كلاسات للصفحة حسب نوعها، وتنفع في التنسيق |
| `wp_body_open()` | نقطة بعد بداية الصفحة، بتستخدمها بعض البلاجن زي أكواد التتبع |

وأهم حاجة: دالة `wp_head()` ودالة `wp_footer()` أهم سطرين في أي قالب. ولو شيلنا دالة `wp_head()`، ملف التنسيق نفسه مش هيتحمّل، والسبب في الباب الجاي.

**خامسًا: الاسم والوصف**
```php
<h1><?php bloginfo( 'name' ); ?></h1>
<p class="tag"><?php bloginfo( 'description' ); ?></p>
```
دالة `bloginfo()` بتطبع اسم الموقع ووصفه من الإعدادات. يعني النص مش مكتوب في الكود، وأي حد يقدر يغيّره من اللوحة.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/reference/functions/wp_head/
https://developer.wordpress.org/reference/functions/language_attributes/
https://developer.wordpress.org/reference/functions/bloginfo/
```

### القالب الكلاسيكي ولا قالب البلوكات؟

ووردبريس فيه نوعين من القوالب:

| النوع | مثال | الصفحات بتتبني إزاي |
|---|---|---|
| قالب البلوكات `Block theme` | قالب ووردبريس الافتراضي `Twenty Twenty-Five` | من بلوكات في محرر الموقع، بملفات `.html` |
| القالب الكلاسيكي `Classic theme` | قالبنا | ملفات PHP بنتحكّم فيها بالكامل |

واخترنا الكلاسيكي لأن التصميم معتمد بالتفصيل (زجاج، وحركات، ومكوّنات مخصّصة)، ومحتاجين نترجمه بالظبط. ومحرر المحتوى هيضيف عظات وأخبار من نماذج محددة، مش هيعدّل شكل الصفحات.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/themes/getting-started/what-is-a-theme/
```

## الباب 4: ملف `functions.php` ونقاط `hooks` وتحميل الملفات

### ملف `functions.php`

ملف اختياري، وووردبريس بيشغّله تلقائيًا مع كل صفحة طول ما القالب مفعّل. وبنحط فيه إعدادات القالب وكوده.

### نقاط `hooks` وهي قلب ووردبريس

ووردبريس وهو بيبني الصفحة بيعدّي على نقط معروفة بالاسم، وفي كل نقطة بيسأل: حد عايز يعمل حاجة هنا؟ والنقط دي اسمها `hooks`، وليها نوعين:

| النوع | معناه | بنسجّل فيه بدالة |
|---|---|---|
| `Actions` | اعمل حاجة هنا | `add_action()` |
| `Filters` | عدّل القيمة دي قبل ما أستخدمها | `add_filter()` |

وليه كده؟ علشان مانعدّلش في ملفات ووردبريس نفسها أبدًا، لأن أي تحديث هيمسح تعديلاتنا. وبدل كده بنتعلّق في النقط دي.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/plugins/hooks/
```

### شرح الكود جزء جزء

**أولًا: ثابت النسخة**
```php
define( 'STMINA_THEME_VERSION', '0.1.0' );
```
ثابت فيه نسخة القالب، وهنستخدمه تحت علشان المتصفح يحمّل ملف التنسيق الجديد بعد كل تعديل.

**ثانيًا: مميزات القالب**
```php
add_action( 'after_setup_theme', function () {
	add_theme_support( 'title-tag' );
	add_theme_support( 'html5', array( 'style', 'script' ) );
} );
```

| الجزء | معناه |
|---|---|
| `after_setup_theme` | نقطة بتشتغل بدري بعد ما ووردبريس يحمّل القالب، وهي المكان الصح لإعلان مميزاته |
| `title-tag` | بنقول لووردبريس إنه هو اللي يكتب عنوان الصفحة من خلال دالة `wp_head()` |
| `html5` | بيخلّي ووردبريس يطبع أكواد التنسيق والسكريبت بصيغة HTML5 النضيفة |

وبسبب ميزة `title-tag`، عنوان التاب في المتصفح بقى "كنيسة السيدة العذراء… – عرب العيايدة، الجبل الأصفر" من غير ما نكتبه.

**ثالثًا: تحميل الخط وملف التنسيق**
```php
add_action( 'wp_enqueue_scripts', function () {
	wp_enqueue_style( 'stmina-fonts', 'https://fonts.googleapis.com/css2?family=Alexandria:wght@200;300;400&display=swap', array(), null );
	wp_enqueue_style( 'stmina', get_stylesheet_uri(), array( 'stmina-fonts' ), STMINA_THEME_VERSION );
} );
```

ليه مانكتبش رابط ملف التنسيق في ملف `index.php` على طول؟ لأن ووردبريس محتاج يعرف كل ملفات CSS وJS في الصفحة، علشان:
- مايتحمّلش ملف مرتين لو بلجن تاني طلبه.
- يرتّبهم صح لو واحد بيعتمد على التاني.
- بلاجن الكاش والضغط تقدر تتعامل معاهم.

والنظام ده اسمه `Enqueue`، والنقطة الصح ليه في الصفحات العامة هي نقطة `wp_enqueue_scripts`، ورغم إن اسمها فيه كلمة سكريبت، بس هي بتاعة ملفات التنسيق كمان.

ودالة `wp_enqueue_style()` بتاخد أربع حاجات:

| الترتيب | القيمة عندنا | معناها |
|---|---|---|
| الاسم | `stmina` | معرّف فريد بالبادئة بتاعتنا |
| الرابط | `get_stylesheet_uri()` | رابط ملف `style.css` في القالب الحالي |
| بيعتمد على | `array( 'stmina-fonts' )` | ووردبريس يحمّل الخط قبل ملف التنسيق |
| النسخة | `STMINA_THEME_VERSION` | بتتضاف لآخر الرابط، وتتشرح تحت |

**إزاي النسخة بتحل مشكلة المتصفح؟** الرابط بيطلع كده:
```
style.css?ver=0.1.0
```
ولما نغيّر النسخة، الرابط يتغيّر، فالمتصفح يحمّل الملف الجديد بدل القديم المحفوظ عنده. ولخط جوجل حطينا القيمة `null` علشان مايتضافش رقم نسخة لرابط مش بتاعنا.

**والملفات دي بتظهر في الصفحة فين؟** جوه دالة `wp_head()`. وعلشان كده لو شيلناها، التنسيق مش هيتحمّل.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/themes/basics/including-css-javascript/
https://developer.wordpress.org/reference/functions/wp_enqueue_style/
https://developer.wordpress.org/reference/functions/add_theme_support/
```

## الباب 5: البلجن وأول مسار في `REST API`

### البلجن فولدر وملف رئيسي

البلجن فولدر جوه مسار `wp-content/plugins/`، وفيه ملف PHP رئيسي غالبًا بنفس اسم الفولدر:
```
st-mina-attendance/st-mina-attendance.php
```

### بطاقة تعريف البلجن

زي ملف `style.css` في القالب، أول تعليق في الملف بيعرّف البلجن:

```php
/**
 * Plugin Name: St Mina Attendance
 * Description: نظام الحضور بالـ QR لخدمة إعداد الخدام. ...
 * Version: 0.1.0
 * Requires at least: 6.5
 * Requires PHP: 8.0
 * Text Domain: st-mina-attendance
 */
```
والسطر الإجباري الوحيد هو `Plugin Name`، ومن غيره البلجن مش هيظهر في صفحة البلاجن.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/plugins/plugin-basics/header-requirements/
```

### الثوابت

```php
define( 'STMINA_ATT_VERSION', '0.1.0' );
define( 'STMINA_ATT_FILE', __FILE__ );
```

| الثابت | فايدته |
|---|---|
| `STMINA_ATT_VERSION` | نسخة البلجن، وهنستخدمها بعدين علشان نعرف لو قاعدة البيانات محتاجة تتحدّث بعد تحديث البلجن |
| `STMINA_ATT_FILE` | مسار الملف الرئيسي، ودوال كتير في ووردبريس محتاجاه |

### التفعيل

```php
register_activation_hook( __FILE__, function () {
	update_option( 'stmina_att_version', STMINA_ATT_VERSION );
} );
```

- **إمتى بتشتغل؟** مرة واحدة بس، لما حد يضغط تفعيل البلجن، مش مع كل صفحة.
- **هنستخدمها في إيه؟** ده المكان اللي هنعمل فيه جداول قاعدة البيانات في المهمة الثامنة (المخدومين، والجلسات، والحضور).
- **بتعمل إيه دلوقتي؟** بتحفظ نسخة البلجن في جدول الإعدادات.

ودوال الإعدادات تلاتة:

| الدالة | بتعمل إيه |
|---|---|
| `update_option()` | بتحفظ قيمة، وبتعملها لو مش موجودة |
| `get_option()` | بتقرا قيمة |
| `delete_option()` | بتمسح قيمة |

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/plugins/plugin-basics/activation-deactivation-hooks/
https://developer.wordpress.org/apis/options/
```

### أول مسار في `REST API`

```php
add_action( 'rest_api_init', function () {
	register_rest_route( 'stmina/v1', '/health', array(
		'methods'             => 'GET',
		'permission_callback' => '__return_true',
		'callback'            => function () {
			return array(
				'plugin'  => 'st-mina-attendance',
				'version' => STMINA_ATT_VERSION,
			);
		},
	) );
} );
```

**يعني إيه `REST API`؟** طريقة ووردبريس الرسمية إن صفحة أو تطبيق يكلّم الموقع ويرجع بيانات بصيغة JSON. وشاشات الحضور كلها (المسح، والجلسات، والمخدومين) هتكلّم البلجن بالطريقة دي.

والكود ده بيعمل الرابط ده:
```
/wp-json/stmina/v1/health
```

| الجزء | معناه |
|---|---|
| نقطة `rest_api_init` | المكان اللي بنسجّل فيه المسارات |
| الاسم `stmina/v1` | البادئة بتاعتنا ورقم نسخة. لو غيّرنا شكل الـ API بعدين، نعمل نسخة تانية من غير ما نكسر القديمة |
| نوع الطلب `methods` | قيمة `GET` للقراية، وقيمة `POST` للإضافة زي تسجيل حضور |
| الدالة `callback` | اللي بترد، وبنرجّع فيها مصفوفة، وووردبريس يحوّلها JSON لوحده |
| الصلاحية `permission_callback` | مين مسموحله، والخانة دي إجبارية من نسخة ووردبريس 5.5 |

**عن الصلاحية:** حطينا القيمة `__return_true` ومعناها أي حد مسموحله. وده مقبول هنا بس لأن المسار بيرجّع اسم البلجن ونسخته. أما أي مسار فيه بيانات مخدومين، فهيبقى فيه فحص صلاحيات حقيقي في المهمة الثامنة، زي كده:
```php
current_user_can( 'stmina_manage_attendance' )
```

**فايدة المسار ده دلوقتي:** نقطة فحص نعرف منها إن البلجن شغال على السيرفر من غير ما ندخل اللوحة.

📖 التوثيق الرسمي:
```
https://developer.wordpress.org/rest-api/extending-the-rest-api/adding-custom-endpoints/
```

## الباب 6: الرفع على السيرفر والكاش

### الرفع

الكود بيتكتب في المستودع على الجهاز، وبيترفع للسيرفر عن طريق ربط هوستنجر في Claude، على تلات خطوات:

| الخطوة | العملية | بتعمل إيه |
|---|---|---|
| الأولى | `hosting_files_generate-upload-url` | بتدّي رابط رفع ومفاتيح مؤقتة للموقع |
| التانية | رفع كل ملف لوحده بطريقة `TUS` | بروتوكول رفع بيكمّل لو النت قطع، وكل ملف على خطوتين: طلب يعلن الحجم، وطلب يبعت المحتوى |
| التالتة | `wordpress_themes_deploy` أو `wordpress_plugins_deploy` | بتحط الملفات في مكانها النهائي بالاسم وتفعّلها |

والملفات بتترفع الأول لفولدر مؤقت زي ده:
```
wp-content/themes/st-mina-u1/
```

**البديل التقليدي:** ضغط الفولدر ورفعه من صفحة القوالب في اللوحة، أو من مدير الملفات في هوستنجر، أو ببرنامج FTP.

### الكاش

بعد الرفع، الصفحة فضلت تظهر بالشكل القديم. والسبب إن هوستنجر بيحفظ نسخة جاهزة من الصفحة علشان يردّ أسرع، فكان بيبعت النسخة المحفوظة.

- **الحل:** مسح الكاش بعد كل رفع بالعملية دي:
```
hosting_cache_clear-website
```
- **إزاي عرفنا؟** لما طلبنا الصفحة برابط فيه رقم عشوائي، الكاش ماكانش عنده نسخة منه، فظهر الشكل الجديد.

## الباب 7: ربط Claude بلوحة ووردبريس

استخدمنا بلجن `royal-mcp`، وهو بيعرض أدوات ووردبريس (قراية وتعديل المحتوى والإعدادات) بطريقة اسمها `MCP`، ودي الطريقة اللي Claude بيتكلّم بيها مع الأدوات.

### نوعين ربط

| | الربط المحلي | الربط على الإنترنت |
|---|---|---|
| بيشتغل منين | برنامج على جهازك بيكلّم الموقع | Claude بيكلّم الموقع مباشرة |
| الدخول | غالبًا كلمة سر تطبيق محفوظة في ملف | موافقة مرة واحدة من صفحة الموقع بطريقة `OAuth` |
| متاح فين | الجهاز ده بس | أي مكان على حسابك |

واخترنا الربط على الإنترنت علشان مافيش كلمة سر بتتحفظ ولا بتتبعت.

### حدود البلجن، وده أمان مقصود

- **تعديل الإعدادات مقفول افتراضيًا،** ومحتاج زرار في إعدادات البلجن اسمه `Allow AI to write WordPress options`.
- **فيه قايمة مسموح بيها بس:** الاسم والوصف اتغيّروا، لكن التوقيت ومحركات البحث اترفضوا، فاتعملوا من اللوحة.
- **إعدادات ممنوعة نهائيًا:** رابط الموقع، وإيميل المدير، والصلاحيات، وأي حاجة فيها كلمة سر أو مفتاح.
- **كل تعديل ليه تراجع** لمدة 72 ساعة، وبيتسجّل في سجل.

ودي فكرة مهمة لما نبني البلجن بتاعنا: أقل صلاحيات ممكنة، والحاجات الحساسة مقفولة من الأساس.

## الباب 8: أخطاء قابلتنا وحلّها

| المشكلة | السبب | الحل |
|---|---|---|
| هوستنجر رفض الاسم العربي وقت التركيب | خانة الاسم في المُركِّب بتقبل حروف لاتيني بس | اسم إنجليزي مؤقت، وبعدين الاسم العربي من الإعدادات |
| الموقع اتركّب إنجليزي | المُركِّب بيستخدم الإنجليزي افتراضيًا، وخطوة اللغة ماظهرتش | تغيير لغة الموقع من الإعدادات العامة |
| الموقع رجع إنجليزي بعد ما اللوحة اتحوّلت إنجليزي | لغة الموقع اتغيّرت بدل لغة المستخدم | لغة الموقع عربي من الإعدادات العامة، ولغة اللوحة من الملف الشخصي |
| قفل محركات البحث ماتحفظش أول مرة | العلامة ماكانتش متعلّمة وقت الحفظ | الرجوع لإعدادات القراية والتأكد منها، والتأكد من سطر القفل في الصفحة |
| الصفحة بالشكل القديم بعد رفع القالب | كاش السيرفر | مسح الكاش بعد كل رفع |
| مش قادرين نفحص أخطاء PHP على الجهاز | لغة PHP مش متثبّتة | الفحص على السيرفر، وبرنامج LocalWP للتشغيل المحلي |
| سجل الأخطاء مش متاح | تسجيل الأخطاء مقفول في ملف `wp-config.php` | هنفتحه وقت التطوير لما نحتاجه، مع إخفاء الأخطاء عن الزوار |

والإعدادات اللي بتفتح سجل الأخطاء من غير ما تظهر للزوار:
```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
```
